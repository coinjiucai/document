# 相关规范

## 代码注释规范

​        **代码的注释应该写在该行代码的上方**。通过将注释放在代码上方，可以帮助阅读者更好地理解代码的含义，无需在代码本身中加入过多的注释。此外，在编辑器或IDE中，通常会显示代码行上方的注释，
**提供更好的可读性和上下文**。

## Commit规范

```html
<type>(<scope>): <subject>
<body>
```

- **type(必须)**

  用于说明git commit的类别，只允许使用下面的标识。

  > **主要：**
  >
  > feat：新特性、新功能
  >
  > fix：修改bug
  >
  >
  >
  > **次要：**
  >
  > build：编译相关的修改，例如发布版本、对项目构建或者依赖的改动，例如 webpack，npm
  >
  > chore：其他修改, 比如改变构建流程、或者增加依赖库、工具等
  >
  > ci：持续集成修改
  >
  > docs：文档修改
  >
  > perf：优化相关，比如提升性能、体验
  >
  > refactor：代码重构
  >
  > revert：回滚到上一个版本
  >
  > style：代码格式修改， 不影响代码含义的改动，例如去掉空格、改变缩进、增删分号，注意不是 css 修改
  >
  > test：测试性调整

- **scope(可选)**

  `scope`用于说明 commit 影响的范围，比如数据层、控制层、视图层等等，视项目不同而不同。我们一般常用于说明**模块**。

- **subject(必须)**

  `subject` 用于说明 `commit` 目的的简短描述，不超过50个字符

- **body(可选)**

  `body` 用于说明 `commit` 的详细描述，内容可以分成多行，主要描述改动之前的情况及修改动机，对于小的修改不作要求，但是重大需求、更新等尽量添加
  body 来作说明

## 版本号规范

**`主版本号.次版本号.修订号-标识符`**

- 主版本号（Major version）：表示重大功能改变或架构更改，通常与向后不兼容的更新相关。
- 次版本号（Minor version）：表示新增功能或特性，但与向后兼容的更新。
- 修订号（Patch version）：表示修复错误、漏洞和其他问题的补丁级更新。
- 标识符：
    1. Alpha版本（α）：表示开发阶段的预览版本，通常包含尚未完全测试和稳定的功能。在版本号中，使用类似于"**1.0.0-alpha**"
       的形式来表示。
    2. Beta版本（β）：表示测试阶段的版本，相对于Alpha版本已经修复了一些错误和缺陷。在版本号中，使用类似于"**1.0.0-beta**"
       的形式来表示。
    3. RC版本（Release Candidate）：表示候选发布版本，是在测试中被认为稳定的版本。在版本号中，使用类似于"**1.0.0-rc**"的形式来表示。
    4. 正式版（GA，General Availability）：表示最终发布的稳定版本，经过充分测试和验证，并且被认为适用于正式环境使用。正式版本没有特定的标识符，只使用主版本号、次版本号和修订号来表示。
    5. 衍生版（Fork）：表示基于某个正式版本独立出去的版本，正常是基于某个项目做出调整的需要用到改标识。在版本号中，使用类似于"
       **1.0.0-fork**"的形式来表示。

## 模块文件注释信息

```html
<!--
  @Name 模块名称
  @Description 描述
  @author 作者
  @date 创建日期
-->
<template>...</template>
```

## 组件文件注释信息

```html
<!--
  @Name 模块名称
  @Description 描述
  @author 作者
  @date 创建日期
  @version 版本号
-->
<template>...</template>
```

## 函数注释信息

```js
/**
* 函数名称
* @param xxx {类型} 属性名称
* @example 示例
* @returns {类型} 返回值描述
* @author 作者
* @version 版本号
*/
functionName(paramName){return '*'};
```

函数的注释内容中`param`、`example`、`returns`、`version`可填可不填，具体看实际情况。
